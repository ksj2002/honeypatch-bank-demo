## 1. 프로젝트 소개

논문 **Honey-Patches**의 핵심 아이디어를 웹 데모로 구현했다.

일반 패치는 공격을 탐지하면 요청을 차단하므로, 공격자는 "막혔다"는 사실을 바로 알 수 있다.
허니 패치는 같은 탐지 지점에서 차단하는 대신 **가짜 환경으로 연결**해서, 공격자가 공격의 성공/실패를 구분하지 못하게 한다.

가상 은행 관리자 로그인에 **의도적인 SQL 인젝션 취약점**을 두고, 같은 공격 입력이 세 가지 모드에서 어떻게 달라지는지 비교한다.

| 모드 | 공격 입력의 결과 |
|---|---|
| VULNERABLE (취약) | 공격 성공. **실제** 고객 데이터가 노출된다. |
| PATCHED (일반 패치) | 인젝션을 탐지해 로그인을 **차단**한다. (HTTP 403) |
| HONEY (허니 패치) | 로그인에 성공한 것처럼 보이지만 **가짜 고객 데이터**를 보여준다. |

### 원논문과의 차이 (구현 범위)
- 화면은 **로그인 / 관리자 2개**뿐이다. 허니 패치용 화면을 따로 만들지 않고, 서버가 같은 화면에 **다른 데이터**를 내려준다.
- 가짜 환경은 **세션 표시(decoy) + 가짜 데이터 테이블**로 단순화했다. 프로세스 분리 같은 격리 환경은 구현하지 않았다.
- 탐지는 규칙 기반 문자열 검사이며, 우회 입력을 모두 막지는 못한다. (13주차 반례 탐색 대상)

## 2. 환경 명세

| 항목 | 내용 |
|---|---|
| OS | Windows 10/11 (macOS, Linux에서도 같은 명령으로 가능) |
| JDK | **17** (`java -version`으로 확인) |
| 백엔드 | Spring Boot **4.1.2**, Gradle (Groovy, 저장소에 포함된 wrapper 사용) |
| DB | H2 인메모리 (별도 설치 없음. 서버 시작 시 `schema.sql`/`data.sql` 실행) |
| 프론트 | HTML, CSS, JavaScript (빌드 도구 없음) |
| 포트 | 백엔드 `8080`, 프론트 `5500` |
| 브라우저 | Chrome 등 최신 브라우저 |

별도로 설치할 패키지는 JDK 17뿐이다. Gradle은 `gradlew`가 내려받는다.

## 3. 실행 방법

### 3-1. 내려받기
```powershell
git clone https://github.com/ksj2002/honeypatch-bank-demo.git
cd honeypatch-bank-demo
```

### 3-2. 백엔드 실행 (터미널 1)
```powershell
cd backend
.\gradlew bootRun        # Windows
./gradlew bootRun        # macOS, Linux
```
- 로그에 `Started HoneypatchBankDemoApplication`이 보이면 성공이다.
- 처음 실행은 라이브러리 다운로드로 몇 분 걸릴 수 있다.
- 종료는 `Ctrl+C`이다.
- 컴파일과 테스트만 확인하려면 `.\gradlew build`를 쓴다.

### 3-3. 프론트 실행 (터미널 2)
프론트는 정적 파일이므로 간단한 웹 서버로 `frontend` 폴더를 **5500 포트**로 열면 된다.

방법 A. Python이 있는 경우
```powershell
cd frontend
python -m http.server 5500
```

방법 B. Node.js가 있는 경우
```powershell
cd frontend
npx serve -l 5500
```

방법 C. VS Code 확장 **Live Server**가 있는 경우: `frontend/index.html`을 열고 우클릭, Open with Live Server

### 3-4. 접속
브라우저에서 **http://localhost:5500** 으로 접속한다.

> ⚠️ **`127.0.0.1`이 아니라 반드시 `localhost`로 접속한다.**
> 서버의 CORS 허용 주소가 `http://localhost:5500` 하나뿐이라, 다른 주소로 열면 로그인 상태(세션 쿠키)가 유지되지 않는다.
> 또한 HTML 파일을 더블클릭해서 `file://`로 열면 동작하지 않는다.

### 3-5. 계정
| 아이디 | 비밀번호 | 용도 |
|---|---|---|
| `admin` | `admin1234` | 정상 로그인 확인용 (데모 계정) |

## 4. 사용 방법

1. 로그인 화면의 "보안 모드 선택" 패널에서 **VULNERABLE / PATCHED / HONEY** 중 하나를 선택한다. (현재 모드가 표시된다. 서버를 재시작하면 `VULNERABLE`로 돌아간다.)
2. 아이디, 비밀번호를 입력하고 로그인한다.
3. 로그인에 성공하면 관리자 화면에서 고객 목록(이름, 잔액)이 표시된다.
4. 관리자 화면의 로그아웃 버튼으로 돌아온다.

## 5. 검증 시나리오와 기대 결과

각 시나리오를 모드별로 실행해 결과를 비교한다.

| 구분 | 아이디 / 비밀번호 | 모드 | 기대 결과 |
|---|---|---|---|
| 정상 | `admin` / `admin1234` | 전부 | 200, **실제** 고객 목록 (홍길동 등) |
| 위반 | `' OR '1'='1' --` / `x` | VULNERABLE | 200, 로그인 우회에 성공해 **실제** 고객 목록 노출 |
| 위반 | 위와 동일 | PATCHED | 403, "허용되지 않는 입력입니다" |
| 위반 | 위와 동일 | HONEY | 200, **가짜** 고객 목록 (김민수 등). 응답 형태는 실제와 동일 |
| 경계 | `o'brien` / `x` | 전부 | 401, "아이디 또는 비밀번호가 올바르지 않습니다" (오탐 없이 일반 로그인 실패) |

### 허니 패치 확인 포인트
- **공격자가 보는 쪽**: 화면과 응답이 정상 로그인과 구분되지 않는다. 고객 이름과 잔액만 가짜다.
- **방어자가 보는 쪽**: 백엔드 터미널에 방어자 전용 로그가 남는다. 응답에는 포함되지 않는다.
  ```
  [DEFENDER] customers 조회 user=... source=... rows=...
  ```
  `source`가 `customers`면 진짜 데이터, `decoy_customers`면 가짜 데이터를 조회한 것이다.

### 인젝션 탐지 기준
입력에 **작은따옴표(`'`)가 있고**, 동시에 SQL 메타 문법(`--`, `/*`, `' OR` / `' AND`, `UNION SELECT`, `;`)이 있을 때만 공격으로 판정한다.
따옴표만 있는 입력(`o'brien`)은 공격으로 보지 않으므로 오탐이 없다. 이 경우 취약 쿼리가 SQL 오류를 내지만, 서버가 이를 일반 로그인 실패(401)로 처리한다.

## 6. API 요약

모든 요청과 응답은 JSON이다. 로그인 상태는 세션 쿠키로 유지하며, 프론트의 `fetch`에는 `credentials: "include"`를 설정한다.

| 메서드 | 경로 | 설명 | 주요 응답 |
|---|---|---|---|
| GET | `/api/mode` | 현재 모드 조회 | `{"mode":"VULNERABLE"}` |
| PUT | `/api/mode` | 모드 변경. 본문 `{"mode":"HONEY"}` | 200 변경된 모드, 400 잘못된 모드 |
| POST | `/api/login` | 로그인. 본문 `{"id":"...","password":"..."}` | 200 성공, 400 빈 입력, 401 실패, 403 차단 |
| POST | `/api/logout` | 로그아웃 | 200 |
| GET | `/api/admin/customers` | 고객 목록 (로그인 필요) | 200 `{"customers":[...]}`, 401 로그인 필요 |

에러 응답 공통 형식은 `{ "message": "설명" }`이다. 요청과 응답 필드의 상세 규격은 [`docs/api.md`](docs/api.md)에 있다.

## 8. 자주 겪는 문제

| 증상 | 원인과 해결 |
|---|---|
| 브라우저 콘솔에 CORS 에러 | 프론트를 `localhost:5500`이 아닌 주소/포트로 열었다. `localhost:5500`으로 접속한다. |
| 로그인 직후 다시 풀림(401) | `127.0.0.1`로 접속했다. `localhost`로 접속한다. |
| `Port 8080 was already in use` | 이전에 켠 서버가 살아 있다. 그 터미널에서 `Ctrl+C`로 종료한다. |
| 서버 시작 시 `'script' must not be null or empty` | `schema.sql` 또는 `data.sql`이 비어 있다. 내용이 있는 파일로 복구한다. |
| 화면은 뜨는데 로그인 버튼이 반응 없음 | 백엔드(8080)가 꺼져 있다. 터미널 1의 서버 상태를 확인한다. |

## 9. 한계

- 모드는 서버 전역 값이다. 접속자마다 다르게 적용되지 않으며, 서버를 재시작하면 초기화된다.
- 모드 변경 API(`PUT /api/mode`)에는 인증이 없다. 데모 편의를 위한 설정이다.
- 탐지는 정규식 기반이라 인코딩, 대소문자 변형, 주석 변형 등의 우회 입력은 막지 못할 수 있다.
- 데모용 계정과 데이터이며 실제 서비스에 사용하지 않는다.
