# 13주차 추가 검증 사례

11주차 고정 사례 3종은 변경하지 않았고, 추가 사례는 이 파일로 따로 관리한다.
기대 결과는 실행 전에 12주차 판정 규칙(작은따옴표 + SQL 구문요소가 함께 있으면 공격)만 보고 작성했으며, 결과를 본 뒤에도 바꾸지 않았다.

## 기대 결과 (실행 전 작성)

| ID | 방향 | id | pw | VULNERABLE | PATCHED | HONEY |
|---|---|---|---|---|---|---|
| A1 | 표기 변형 | `' or '1'='1' --` | `x` | 200, 실제 목록 | 403 | 200, 가짜 목록 |
| A2 | 표기 변형 | `'  OR  '1'='1' --` (OR 앞뒤 공백 2칸) | `x` | 200, 실제 목록 | 403 | 200, 가짜 목록 |
| A3 | 필드 위치 | `admin` | `' OR '1'='1' --` | 200, 실제 목록 | 403 | 200, 가짜 목록 |
| A4 | 필드 분리 | `admin'` | ` OR 1=1 --` (앞 공백 1칸) | 200, 실제 목록 | 403 | 200, 가짜 목록 |
| B1 | 오탐 후보 | `o'brien` | `a;b` | 401 | 403 | 200, 가짜 목록 |
| B2 | 오탐 후보 | `admin` | `pass--word` | 401 | 401 | 401 |
| B3 | 오탐 후보(같은 필드) | `o'brien;` | `x` | 401 | 403 | 200, 가짜 목록 |
| S1 | 상태 전이 | HONEY에서 A1로 로그인, 고객 목록 조회, 로그아웃, `admin`/`admin1234`로 재로그인 | | - | - | 공격 세션은 가짜 목록, 재로그인 후는 실제 목록 |

| ID | 수정 전 | 수정 후 |
|---|---|---|
| A1 | 기대와 일치 | (재시험 안 함) |

## 반례

- C1 (B1): 기대 403/가짜 목록, 실제 401/401. 필터가 필드별로 판정한다는 것을 B3으로 확인. 수정 없음.
- C2 (A4): 필드를 나눈 공격이 PATCHED, HONEY에서 모두 통과. 구현 버그, `InjectionFilter.decide()`에 id+pw 합친 검사 추가로 수정.

## 실행 방법

브라우저 로그인 화면에서 모드를 바꿔 입력. 상태 코드는 개발자도구 Network 탭,
실제/가짜 목록 구분은 화면과 백엔드 로그의 `source=` (`customers` / `decoy_customers`)로 확인.
